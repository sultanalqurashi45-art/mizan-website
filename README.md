# ميزان — دليل التشغيل والرفع

## محتوى المشروع

```
mizan-project/
├── index.html      الصفحة الرئيسية (الهيكل فقط)
├── css/
│   └── style.css   كل التنسيقات
├── js/
│   └── app.js      كل السكربتات (الحاسبات، رفع الملفات، التسجيل، الدفع...)
└── README.md        هذا الملف
```

هذه **واجهة أمامية فقط (Front-end)**. لا يوجد خادم ولا قاعدة بيانات. يعني ذلك:
- التسجيل والتحقق برمز الجوال والدفع **محاكاة**، تُحفظ في متصفح الزائر نفسه (localStorage) ولا تصل إلى أي خادم.
- تدقيق المستندات بالذكاء الاصطناعي يعمل فقط عند فتح الصفحة داخل claude.ai كـ Artifact. عند رفعه كموقع عادي (GitHub Pages أو غيره) **لن يعمل زر "ابدأ التدقيق"** لأنه يعتمد على واجهة خاصة بمعاينة Claude.

هذا الدليل يشرح كيف تفتحه محليًا، وترفعه على الإنترنت كموقع تعريفي/تجريبي يعمل بالكامل ما عدا التدقيق بالذكاء الاصطناعي. القسم الأخير يشرح ما تحتاجه لتشغيل التدقيق الحقيقي.

---

## 1. فتح المشروع في VS Code

1. ثبّت [Visual Studio Code](https://code.visualstudio.com/) إن لم يكن مثبتًا.
2. ثبّت امتداد **Live Server** (من Ritwick Dey) من متجر الإضافات داخل VS Code (أيقونة المربعات الأربعة في الشريط الجانبي، ابحث عن Live Server، اضغط Install).
3. افتح مجلد `mizan-project` كاملًا: من القائمة File → Open Folder.
4. افتح `index.html`، ثم اضغط بزر الفأرة الأيمن داخل الملف واختر **Open with Live Server**، أو اضغط الزر الصغير أسفل يمين الشاشة "Go Live".
5. سيفتح المتصفح تلقائيًا على عنوان مثل `http://127.0.0.1:5500`. جرّب الموقع من هناك.

**لماذا Live Server ولا فتح الملف مباشرة بنقرتين؟**
لأن المتصفحات تمنع أحيانًا تحميل ملفات JS منفصلة عند فتح HTML مباشرة من القرص (file://). Live Server يشغّل خادمًا محليًا بسيطًا يحل هذه المشكلة، وهو ما ستحتاجه لاحقًا فعليًا أيضًا.

## 2. رفع المشروع على GitHub

### أ. إنشاء حساب ومستودع
1. أنشئ حسابًا على [github.com](https://github.com) إن لم يكن لديك.
2. اضغط على "+" أعلى الصفحة → **New repository**.
3. اسم المستودع مثلًا: `mizan-website`. اجعله **Public** (لازم لاستخدام GitHub Pages مجانًا). لا تضف README لأن لديك واحدًا بالفعل.
4. اضغط **Create repository**.

### ب. رفع الملفات من VS Code
أسهل طريقة داخل VS Code نفسه:
1. ثبّت Git على جهازك إن لم يكن مثبتًا: [git-scm.com](https://git-scm.com/downloads).
2. من داخل VS Code، افتح الطرفية (Terminal → New Terminal) وتأكد أنك داخل مجلد المشروع، ثم نفّذ الأوامر التالية واحدًا تلو الآخر:

```bash
git init
git add .
git commit -m "النسخة الأولى من موقع ميزان"
git branch -M main
git remote add origin https://github.com/USERNAME/mizan-website.git
git push -u origin main
```

استبدل `USERNAME` باسم مستخدمك على GitHub. سيطلب منك تسجيل الدخول عبر المتصفح أو بكلمة مرور/رمز وصول (Personal Access Token) — اتبع التعليمات التي تظهر.

**بديل بلا أوامر:** من صفحة المستودع على GitHub اضغط **Add file → Upload files**، ثم اسحب مجلدات `css` و`js` وملف `index.html` و`README.md` وارفعها مباشرة من المتصفح.

---

## 3. نشر الموقع مجانًا (GitHub Pages)

1. داخل مستودعك على GitHub اذهب إلى **Settings** (أعلى يمين الصفحة).
2. من القائمة الجانبية اختر **Pages**.
3. تحت "Build and deployment"، اختر Source: **Deploy from a branch**.
4. اختر Branch: **main**، والمجلد **/ (root)**، ثم اضغط **Save**.
5. انتظر دقيقة أو دقيقتين، وسيظهر رابط مثل:
   `https://USERNAME.github.io/mizan-website/`
6. افتح الرابط وتأكد أن الموقع يعمل (التسجيل والدفع التجريبي وحاسبات الزكاة والاستقطاع وتقويم الامتثال). زر التدقيق بالذكاء الاصطناعي لن يعمل هنا كما ذكرنا.

### خيارات نشر أخرى (بنفس السهولة تقريبًا)
- **Netlify** (netlify.com): اسحب مجلد المشروع مباشرة إلى صفحتهم الرئيسية بعد تسجيل الدخول، وينشره فورًا برابط مجاني، ويدعم لاحقًا ربط دومين خاص ووظائف خادم بسيطة (Functions) قد تحتاجها لاحقًا للتسجيل الحقيقي.
- **Vercel** (vercel.com): مشابه لـ Netlify، ويربط تلقائيًا بمستودع GitHub فيعيد النشر كل مرة تدفع فيها تحديثًا (git push).
- كلاهما يوفر HTTPS مجانًا تلقائيًا، وهو ضروري لأي موقع فيه نماذج تسجيل أو دفع.

---

## 4. ربط دومين خاص بك (مثل mizan.sa أو mizan.com)

1. اشترِ الدومين من مسجّل نطاقات (مثل GoDaddy، Namecheap، أو "سوا" السعودية لنطاقات .sa).
2. في إعدادات GitHub Pages (Settings → Pages)، أدخل الدومين في خانة **Custom domain**.
3. من لوحة تحكم الدومين لديك، أضف سجلات DNS كما يوضح GitHub في نفس الصفحة (عادة سجل CNAME يشير إلى `USERNAME.github.io`).
4. انتظر حتى تنتشر الإعدادات (قد تأخذ من دقائق إلى 24 ساعة)، وفعّل **Enforce HTTPS** بعد ظهورها.

---

## 5. تعديل المحتوى لاحقًا

- **النصوص والأسعار:** عدّلها مباشرة داخل `index.html` (ابحث بـ Ctrl+F عن النص الذي تريد تغييره).
- **الألوان والتنسيق:** كلها في `css/style.css`، معرّفة كمتغيرات في أول الملف تحت `:root{...}` مثل `--em` (الأخضر الرئيسي) و`--gold` (الذهبي).
- **الحاسبات والسلوك:** كلها في `js/app.js`.

بعد أي تعديل محلي، أعد الرفع بهذه الأوامر من طرفية VS Code:
```bash
git add .
git commit -m "وصف التعديل"
git push
```
سيحدَّث الموقع المنشور تلقائيًا خلال دقيقة أو دقيقتين (مع GitHub Pages أو Vercel).

## 6. ما الذي يبقى وهميًا، وما تحتاجه لتشغيله فعليًا

| الميزة | الحالة الآن | لتشغيلها فعليًا |
|---|---|---|
| تدقيق المستندات بالذكاء الاصطناعي | يعمل فقط داخل معاينة claude.ai | خادم خاص بك يستدعي نموذج ذكاء اصطناعي عبر API، ويعالج الملفات |
| التسجيل والتحقق برمز الجوال | وهمي، محفوظ في متصفح الزائر فقط | خادم + قاعدة بيانات + مزوّد رسائل SMS مرخّص |
| الدفع (مدى/Apple Pay/فيزا) | محاكاة كاملة، لا مال حقيقي | حساب تاجر مع مزوّد دفع مرخّص في السعودية (مثل Moyasar أو HyperPay أو Tap) |
| حفظ التقارير عبر الأجهزة | محلي في كل متصفح فقط | قاعدة بيانات مركزية |

راجعت معك هذه النقطة سابقًا في وثيقة "الخطة التقنية للانتقال إلى منتج حقيقي" — ابدأ بها عندما تريد تطوير هذه الأجزاء.

## أسئلة شائعة سريعة

**الموقع لا يظهر بشكل صحيح بعد الرفع على GitHub Pages؟**
تأكد أن أسماء المجلدات بحروف صغيرة `css` و`js` تمامًا كما في `index.html`، لأن بعض الاستضافات حساسة لحالة الأحرف بعكس أنظمة التشغيل مثل ويندوز.

**أريد تجربة تعديل قبل نشره؟**
عدّل الملف محليًا وشغّل Live Server، وتأكد أن كل شيء يعمل، ثم ادفع (`git push`) فقط عند الرضا عن النتيجة.

**كيف أرجع نسخة سابقة إذا أخطأت؟**
```bash
git log --oneline
git checkout <رقم النسخة القديمة> -- .
```
أو ببساطة من موقع GitHub: تبويب Commits → اختر نسخة قديمة → View file.
